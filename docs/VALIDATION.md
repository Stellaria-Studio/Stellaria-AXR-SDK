## Guard 并发与性能

八个线程共用 Guard、总计尝试 64 次、授权额度 32 次：修正前复现 8 次成功及 56 次非预期
事务错误；修正后精确消费 32 次，其余按额度拒绝，没有嵌套事务错误。
同时覆盖短期旧许可与新精确许可、过期、单次额度、撤权后复查及策略 MAC 篡改。

在同一本机、Release 构建、1,000 条有效合成宽授权的查找微基准中，以 A/B/B/A 顺序测量。
每次取五组、每组 20 次查找的中位数：

| 顺序 | 构建 | 每次查找中位延迟 |
| --- | --- | --- |
| A | 修正前 | 11.290 ms |
| B | 修正后 | 6.706 ms |
| B | 修正后 | 6.677 ms |
| A | 修正前 | 10.771 ms |

两轮中位数的平均值约 11.031 → 6.691 ms，降低约 39.3%。合成基准不访问账号或真实应用。
没有据此宣称整套 Agent、数据库审计、实际业务、CPU/功耗或所有机器都获得相同比例提升。
可复现源码见 [GuardLookup.cpp](../benchmarks/GuardLookup.cpp)。

## 尚未覆盖的资格

- Windows Hello/TPM、AppContainer 及真实部署仍需目标设备验收；新 CI 只能提供所执行的合成/构建证据。
- Linux 不包含完整等效的所有者硬件与安装边界。
- 当前受保护部署仍有原产品兼容 profile；任意应用的独立打包、签名和注册是集成工作。
- 未验收多日无人值守、整体功耗、任意第三方应用控制或稳定 ABI。

本机详细构建、测试和基准日志留在被忽略的 `.local-build/`；不公开个人部署或设备凭据。
